# Hermes Adapter

- Inspect the current Hermes installation, persistent host skill source, mounted runtime path, tool inventory, media providers, binaries, and credential mechanisms before deployment.
- Keep Ruby-specific credentials, account IDs, project state, character packages, and generated media outside the distributable skill.
- Do not copy OpenClaw configuration fields into Hermes. Recreate approved provider routes using Hermes-native tools, plugins, MCP, or ZedBiz adapters.
- Confirm the live audio, video-generation, avatar, transcription, assembly, and file-download routes separately.
- Treat a host or repository copy as authoritative; never create a competing container-only skill.
- Run discovery and a no-cost inspection or explicitly approved controlled proof in a fresh session before claiming readiness.
